Report your store's online purchases to TikTok Ads from the server, so TikTok can credit each sale to the ad that brought the shopper, and its bidding learns who buys. Ad blockers, closed tabs and browser privacy rules stop many purchases that a browser Pixel would report. A purchase sent from Swell's servers through TikTok's Events API is stopped by none of them.

Connect your TikTok Pixel with its Pixel code and an access token from TikTok Ads Manager. No TikTok developer account is needed. The app runs inside Swell, with no other service in between, and only reads your store: it changes no orders, carts or customers.

- **Every online order, once.** When a shopper places an order through your storefront, TikTok gets a Purchase with the order's value, currency and products, identified by SKU. The event id is the order id, so a retried delivery is never counted twice. Orders created in the dashboard, subscription renewals and orders imported by other apps are not sent.
- **Matched to the shopper.** Each purchase carries the customer's email, phone, customer id, name and zip code, hashed with SHA-256 as TikTok requires, plus their city, state and country.
- **The click id too, with one small storefront change.** Your storefront's developer adds two touch points, about 15 lines, that hand TikTok's click id, the TikTok Pixel's cookie and the shopper's IP address and user agent to the app. The app guide includes a ready-made prompt for an AI coding agent that adds them. Without a developer, paste the checkout snippet into your checkout's head scripts for the IP address and user agent.
- **Works next to the TikTok Pixel.** A Pixel that also fires Purchase with the order id as its event id is merged with the server copy, so each sale counts once.
- **Check it before it counts.** Test connection checks the Pixel code and token with TikTok without sending an event. With a test event code, purchases appear only in the Pixel's Test events tab, where TikTok shows their value, products and match keys.
- **Nothing lost quietly.** If TikTok refuses the token or the Pixel code, your store's administrators get an email that says how to fix it. Purchases keep being retried for 47 hours and go out with their original times once the token is fixed. If TikTok refuses the details of a purchase, the administrators hear of that too.

Setup takes a few minutes. In TikTok Ads Manager, open Tools > Events, create a web Pixel with "TikTok Pixel + Events API", copy its Pixel code, and generate an access token in the Pixel's settings. In Swell, paste both in the app settings, save, choose Test connection, and turn on Send purchases to TikTok. Then add the storefront touch points or the checkout snippet. Your test and live environments have separate settings, so you can try the app with a test event code first.

The app sends Purchase only. TikTok's Diagnostics therefore shows "Missing events" for the Pixel: page views, ViewContent, AddToCart and InitiateCheckout come from the TikTok Pixel on your storefront, which TikTok recommends for the full funnel.

Email, phone, customer id, name and zip code leave Swell hashed. City, state, country and locale, and the shopper's IP address, user agent, click id and TikTok cookie, are sent in clear, as TikTok requires; the app collects the last four from the storefront or checkout and deletes them once the purchase is sent, or after 7 days. TikTok's server events have no consent flag, so where your shoppers' consent is required, gate the storefront touch points and the checkout snippet with your consent tool, and decide whether to use the app. TikTok does not allow data about health, finances or children, also in product names: stores in those categories should not use it.
